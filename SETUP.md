# Setup Guide

## 1. Folder structure

Your GitHub profile README lives in a special repo named exactly after your username:
`github.com/maczeo11/maczeo11`. If it doesn't exist yet, create it as a **public** repo.

```
maczeo11/
├── README.md
├── assets/
│   ├── banner.svg
│   ├── architecture.svg
│   └── footer.svg
└── .github/
    └── workflows/
        └── snake.yml
```

Copy these four files into that repo at the paths shown, commit, and push to `main`.
GitHub will render `README.md` on your profile page automatically — no build step needed.

## 2. Enable the contribution snake (optional, one-time)

The snake animation at the bottom of the README is generated by a GitHub Action, not a
third-party server, so it won't go down or rate-limit you.

1. Push `.github/workflows/snake.yml` to the repo.
2. Go to **Settings → Actions → General** in that repo and make sure "Read and write
   permissions" is selected under Workflow permissions (needed for the Action to push
   the generated SVG to the `output` branch).
3. Go to the **Actions** tab and manually run "Generate Snake Animation" once — after
   that it regenerates itself daily on the schedule already in the workflow file.
4. The README already points at
   `https://raw.githubusercontent.com/maczeo11/maczeo11/output/github-contribution-grid-snake-dark.svg` —
   nothing else to configure.

If you'd rather skip this entirely, just delete the last `<img>` block in the README
under `## GitHub Activity` — the stats card above it works standalone.

## 3. No API tokens required

Every service used (`readme-typing-svg`, `github-readme-stats`, `skillicons.dev`,
`shields.io`, the `Platane/snk` Action) works off your public GitHub username with no
personal access token or secret needed. `GITHUB_TOKEN` in the workflow is the one
GitHub Actions provides automatically per run — you don't create or paste anything.

## 4. Required URLs to update if your username or handles change

Search the README for `maczeo11` and replace every instance with your GitHub username
— it appears in the typing SVG link, the badge links, the two project repo links, the
stats card URL, and the snake animation URL. Also update the LinkedIn, email, and
LeetCode URLs in the badge row at the top.

## 5. Customization guide

- **Colors**: the palette is `#a371f7` (accent purple) / `#0d1117` (GitHub dark
  background) / `#6e40c9` (deep purple), matching GitHub's own dark-mode accent so the
  banner doesn't clash with the rest of your profile. Change the `stop-color` values in
  `banner.svg`, `architecture.svg`, and `footer.svg` to re-theme.
- **Typing line rotation**: edit the `lines=` query parameter in the typing SVG URL near
  the top of `README.md` — each `;`-separated phrase is one line in the rotation.
- **Adding a project**: copy one of the existing project blocks (heading, 1-sentence
  framing, 3–4 bullets on the interesting engineering problem, tech badges, repo link)
  rather than inventing a new format — the whole page relies on every project following
  the same shape so it scans quickly.
- **Architecture diagram**: `architecture.svg` is hand-built, not generated — open it in
  any text editor and adjust the `<rect>`/`<text>`/`<line>` elements directly, or use it
  as a template for a second diagram if you want to showcase another project's system
  design instead of (or alongside) PRAJNA's.
